# CarSpotter — контекст проекта

## Что это
Telegram-бот + Mini App (WebApp) для коллекционирования автомобилей.
Пользователь фотографирует машину → ИИ определяет марку/модель/год →
машина сохраняется в личный "Гараж". Концепция — что-то вроде Pokémon GO
для автомобилей.

Полное описание игровой механики (Гараж / Охота / Коллекция, будущие
достижения и задания) — см. в истории обсуждения с пользователем,
при необходимости попроси пересказать.

## Текущий стек (реальность на момент аудита)
- Backend: FastAPI + SQLAlchemy async + PostgreSQL (через psycopg)
- Бот: aiogram 3
- Frontend: один файл index.html (WebApp), без фреймворка
- Хостинг сейчас: Railway (backend), БД — облачная (Supabase/Neon)
- Фото: сохраняются на локальный диск backend (`uploads/`), отдаются
  через `/api/cars/photo/{filename}`
- AI: должен вызывать OpenRouter (`app/services/recognition.py`),
  но пока не подключён к роутерам

## Известные баги (найдены при аудите, на момент начала работы)
1. `recognition.py` импортирует `RecognizeResult` из `app/schemas.py`,
   но такого класса там нет — упадёт при импорте.
2. `recognition.py` нигде не используется ни в одном роутере — эндпоинта
   `/api/cars/recognize` физически не существует. Сейчас распознавание
   вообще не работает, фронт использует только ручной ввод марки/модели.
3. `app/routers/game.py` в `get_collection` обращается к
   `car.photo_file_id`, которого нет в модели `Car` (там есть `photo_url`).
   Упадёт при вызове `/api/game/collection/{telegram_id}`.
4. `app/services/telegram_files.py` (скачивание фото по Telegram file_id)
   нигде не используется — мёртвый код, но может понадобиться, если
   вернём приём фото через бота напрямую.
5. CORS сейчас `allow_origins=["*"]` — нормально для разработки,
   недопустимо для продакшена.

Проверяй актуальность этого списка — часть багов может быть уже
исправлена в текущих сессиях.

## Целевая архитектура (куда переезжаем)

```
Пользователь → Telegram → aiogram бот → Telegram WebApp
                                              ↓
                                   Nginx (HTTPS, домен REG.RU)
                                              ↓
                                     FastAPI (Docker-контейнер)
                                    ↓                        ↓
                        PostgreSQL (Docker,          Файловое хранилище
                        постоянный диск)              фото (том Docker)
                                              ↓
                                        OpenRouter (Qwen vision)

Мониторинг (отдельный docker-compose стек):
Prometheus + Node Exporter → метрики хоста и приложения
Loki + Alloy               → централизованные логи
Grafana                    → дашборды поверх Prometheus + Loki
```

Всё — на одном VDS в Selectel, через Docker Compose. Домен куплен на
REG.RU, DNS указывает на VDS.

## План миграции (14 этапов)

1. Создать VDS в Selectel
2. Настроить SSH-доступ + установить Docker/Docker Compose
3. Подключить домен REG.RU (DNS A-запись на IP VDS)
4. Nginx + HTTPS (Let's Encrypt / certbot)
5. PostgreSQL в Docker + постоянный диск (volume)
6. Перенести FastAPI backend на VDS (Docker-контейнер)
7. Перенести Telegram-бота на VDS
8. Нормальное хранение фотографий (постоянный volume, не эфемерный диск)
9. Подключить OpenRouter по-настоящему (починить баги 1-2 выше)
10. Prometheus + Node Exporter — базовые метрики хоста/приложения
11. Loki + Alloy — сбор логов со всех контейнеров
12. Grafana — дашборды поверх Prometheus и Loki
13. Бэкапы PostgreSQL и фотографий (регулярные, с ротацией)
14. Перенос существующих данных из Railway/Supabase на новый VDS

### Как идём по этапам
- Работаем строго последовательно, один этап = один законченный кусок
  работы с моим подтверждением перед переходом дальше.
- Часть этапов (1, 3 — создание VDS, покупка/настройка DNS в панели
  REG.RU) я делаю руками в веб-панелях — в этих случаях давай мне
  пошаговую инструкцию с точными полями/кнопками, а не пытайся сделать
  это сам.
- Остальные этапы (SSH-настройка, Docker, конфиги, деплой) можешь
  выполнять через терминал, если у тебя есть SSH-доступ к серверу —
  спроси данные для подключения, когда дойдём до этого этапа.

## Долгосрочная цель (держать в уме при проектировании схемы БД и API)
Не просто бот, а социальная платформа: публичные профили и коллекции,
рейтинги, карта находок, лента активности, лайки/комментарии, редкость
машин, городские рейтинги, игровые сезоны. Не над-инженерить сейчас,
но не закладывать архитектуру, которая это исключит (например, публичные
коллекции уже сейчас требуют отделить "видимость профиля" от auth).
